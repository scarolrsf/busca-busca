# Instruções para colaboradores

Sarah determinou que a documentação do projeto fique em dois documentos, na raiz desta pasta:

- **README.md** — o estado atual: requisitos, arquitetura, dados, operação, conferências e pendências em aberto.
- **HISTORICO.md** — o registro datado de cada alteração, da mais recente para a mais antiga.

Regras:

- Leia o README.md antes de iniciar ou retomar trabalho; consulte o HISTORICO.md quando precisar do porquê de uma decisão.
- A cada alteração, atualize no mesmo trabalho as seções afetadas do README e acrescente uma entrada datada no topo do HISTORICO.md, com responsável, motivo, arquivos, validação, efeito nos dados/implantação e pendências. Siga a seção “Regra permanente de atualização” do README.
- Mantenha a seção “Pendências em aberto” do README em dia: acrescente o que ficou pendente e retire o que foi resolvido.
- Atualize o inventário quando mudar a estrutura ou a função dos arquivos. Não crie outro documento concorrente para o estado atual do projeto; evidências antigas podem ser preservadas e referenciadas.
- Diferencie implementação local, testes com amostras, consultas reais às fontes e publicação no GitHub Pages. Não registre sucesso simulado como atualização oficial ou confirmação jurídica.
- Preserve instruções e requisitos de Sarah. A divisão atual é Claude Code na interface e Codex na revisão de arquitetura e dados, até nova orientação.
- Confira alterações concorrentes antes de gravar, especialmente o README e o HISTORICO. Releia e concilie o conteúdo mais recente; não sobrescreva o trabalho de outro colaborador.
- Não inclua credenciais, cookies, tokens ou conteúdo de sessão na documentação.

Estas são instruções de manutenção. O conhecimento do projeto fica no README.md, e o histórico no HISTORICO.md.
